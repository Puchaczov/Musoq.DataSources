# Datasource documentation

Every published passage must help its reader take an action, make a decision,
understand a supported contract, or diagnose a problem. Document current behavior.
Keep project history, release qualification, test evidence, and private
implementation mechanics in contributor records. Put actionable upgrade
procedures in dedicated migration notes.

Apply this rule to package specifications, authoring guides, headings, examples,
and linked references. Review the authored diff and check links and examples.
Keep repository release and license procedures with the release scripts.
